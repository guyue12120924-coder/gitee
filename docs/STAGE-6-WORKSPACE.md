# Stage 6 · Workspace Layout

第六阶段把原来的纵向卡片页面升级为桌面创作工作台，但不改变现有模型 Registry、Adapter、API Proxy、任务跟踪和历史存储逻辑。

## 桌面结构

```text
多模型创作工作台

┌────────────────────────┬──────────────────────────────────┐
│ 左侧控制区             │ 右侧预览 / Output               │
│                        │                                  │
│ API / Token            │ 当前工作流 / 当前模型 / 状态    │
│ 工作流快速切换         │                                  │
│ 当前模型               │ 图片 / 视频结果                 │
│ Prompt                 │                                  │
│ Adapter 参数           │                                  │
│ Generate               │                                  │
└────────────────────────┴──────────────────────────────────┘

生成任务 / Generation Tasks
生成历史 / History
```

宽屏下左侧控制区保持 sticky，并拥有独立滚动；右侧输出区域保持较大的预览空间。900px 以下自动退化为单列布局，避免影响移动端使用。

## 工作流切换

原来的 `#modelSel` 继续作为兼容状态源，但桌面 UI 使用四个工作流按钮：

- 文生图
- 图像编辑
- 图生视频
- 文生视频

点击按钮会同步更新 `#modelSel` 并触发现有 `change` 事件，因此原有面板显示、历史恢复和生成逻辑不需要重写。

## 预览区

右侧新增三个状态摘要：

- 当前工作流
- 当前模型
- 运行状态

它们分别跟随顶层工作流选择、模型选择器和 `#statusBadge` 自动更新。

输出为空时显示统一空状态；一旦 `#output` 中出现结果卡片，空状态自动隐藏。

## 任务与历史

`#taskCenter` 与 `#historyCenter` 会移动到工作区底部的全宽区域。这里只调整 DOM 布局，不修改任务中心和历史中心本身的数据逻辑。

## 文件

- `workspace.css`：双栏工作台、sticky 侧栏、预览空状态、响应式布局
- `js/ui/workspace-layout.js`：组合现有卡片、工作流快捷按钮、预览摘要、任务/历史布局

`index.html` 在基础样式后加载 `workspace.css`，并在任务中心、历史中心之后加载 `workspace-layout.js`，保证布局层只负责最后的页面编排。
